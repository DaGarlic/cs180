1.1 Convolution from scratch

Convolving an image with a kernel means flipping the kernel, sliding it over the image, and at every position multiplying it against the pixels underneath and summing the result. I wrote this in numpy only, first with four nested loops and then with two, on a zero-padded copy of the image. scipy.signal.convolve2d is used only as the reference to check against, and cv2 only reads and saves images.

Padding

Both versions pad the image with zeros first so the kernel can be centered on the edge pixels. For an image of size H×W and a kernel of size kh×kw:

ModeTop / left paddingBottom / right paddingOutput size
samekh−1−(kh−1)//2  /  kw−1−(kw−1)//2(kh−1)//2  /  (kw−1)//2H × W
fullkh−1  /  kw−1kh−1  /  kw−1(H+kh−1) × (W+kw−1)

For an odd kernel, "same" padding is just k//2 on every side. For an even one, like the 1×2 Dx and 2×1 Dy below, the padding can't be symmetric, so the extra row or column goes on the top or left. That choice is what makes the output line up with scipy's mode="same". 

def pad_img(image, kernel, mode="same"):
    # Zero pad the image ("same" keeps the output size, "full" gives every position the kernel overlaps)
    height, width = image.shape[:2]
    kernel_h, kernel_w = len(kernel), len(kernel[0])
    if mode == "full":
        top, left = kernel_h - 1, kernel_w - 1
        bottom, right = kernel_h - 1, kernel_w - 1
    elif mode == "same":
        bottom, right = (kernel_h - 1) // 2, (kernel_w - 1) // 2
        top, left = kernel_h - 1 - bottom, kernel_w - 1 - right
    else:
        raise ValueError(f"Unknown padding mode: {mode}")

    padded_image = np.zeros((height + top + bottom, width + left + right))
    padded_image[top:top + height, left:left + width] = image
    return padded_image

Four loops

The outer two loops visit every output pixel, and the inner two loops walk over the kernel, accumulating one product at a time. The flip is the [::-1, ::-1] on the kernel, which reverses it along both axes. 

def convol_img(image, kernel, mode="same"):
    # Perform convolution of the image with the given kernel (four for loop implementation)
    kernel_h, kernel_w = len(kernel), len(kernel[0])
    padded_image = pad_img(image, kernel, mode)
    flipped_kernel = np.array(kernel)[::-1, ::-1]
    height = padded_image.shape[0] - kernel_h + 1
    width = padded_image.shape[1] - kernel_w + 1
    output_image = np.zeros((height, width))

    for i in range(height):
        for j in range(width):
            sum_val = 0.0
            for ki in range(kernel_h):
                for kj in range(kernel_w):
                    sum_val += padded_image[i + ki][j + kj] * flipped_kernel[ki][kj]
            output_image[i][j] = sum_val

    return output_image

Two loops

The two inner loops are replaced by one array operation. I slice out the kernel-sized window of the padded image at the current pixel, multiply it elementwise with the flipped kernel, and sum the result with np.sum. 

def convol_img_2loops(image, kernel, mode="same"):
    # Perform convolution of the image with the given kernel (two for loop implementation)
    kernel_h, kernel_w = len(kernel), len(kernel[0])
    padded_image = pad_img(image, kernel, mode)
    flipped_kernel = np.array(kernel)[::-1, ::-1]
    height = padded_image.shape[0] - kernel_h + 1
    width = padded_image.shape[1] - kernel_w + 1
    output_image = np.zeros((height, width))

    for i in range(height):
        for j in range(width):
            output_image[i][j] = np.sum(padded_image[i:i + kernel_h, j:j + kernel_w] * flipped_kernel)

    return output_image

The kernels

The box filter averages a 9×9 neighborhood, so each entry is 1/81 and the kernel sums to 1. Dx and Dy are the finite difference operators. Because convolution flips the kernel, convolving with [1, -1] gives f(x) − f(x−1), the final value minus the initial one, so an edge that gets brighter to the right comes out positive. 

Dx = [[1, -1]]
Dy = [[1], [-1]]

def box_kernel(size):
    # Generate a 2D box filter kernel (every entry is 1 / size^2 so it sums to 1)
    kernel = []
    for i in range(size):
        row = []
        for j in range(size):
            row.append(1 / size**2)
        kernel.append(row)
    return kernel

Checking against scipy

The reference call zero-fills the border the same way my padding does. I run all three implementations on the same image and kernel, in both padding modes, and take the largest difference between their outputs. 

def convol_with_scipy(image, kernel, mode="same"):
    return scipy.signal.convolve2d(image, kernel, mode=mode, boundary="fill", fillvalue=0)

The four-loop version does one Python-level multiply-add per kernel entry per pixel, about 100 million of them for the 9×9 box filter, so its time grows with the kernel: 26 s for the box filter against about 1 s for the two-entry Dx and Dy. The two-loop version makes a handful of NumPy calls per pixel instead, so its time barely depends on the kernel, about 2.5 s for all three. That makes it roughly 10 times faster for the box filter, but about 2.5 times slower for Dx and Dy, where the four-loop version only has two products to add and NumPy's per-call overhead costs more than it saves. scipy is much faster than either: 0.084 s for the box filter, about 30 times faster than my two-loop version and 300 times faster than the four-loop one, and about 0.01 s for Dx and Dy, because its loops run in compiled code instead of Python.

Boundary handling

Both implementations pad with zeros, which is the fill convolve2d uses by default, so the outputs match scipy up to floating-point rounding (a largest difference of 6.3e-13 for the box filter and 0 for Dx and Dy). Zero padding only affects the outermost pixels: the box filter darkens the outer 4 pixels because it averages in zeros, and Dx and Dy pick up a one-pixel edge along the left and top border respectively. scipy can also reflect or wrap at the border, but I only implemented zero fill.

1.2 Finite difference operator

I convolved the cameraman image with the finite difference operators from Part 1.1, using my own four-loop convolution with "same" padding. Dx gives the partial derivative Ix in x and Dy gives the partial derivative Iy in y. The gradient magnitude, sqrt(Ix² + Iy²), combines the two into a single edge-strength image that doesn't depend on which way the edge points.

Two things needed handling first. The cameraman file has a white frame around it (7 px at the top, 5 at the right, 1 at the bottom and left), which would show up as a strong fake edge all the way round, so I crop it off, leaving 534×534. And zero padding makes the first column of Dx and the first row of Dy raw pixel values instead of differences, so I set those to zero.

Choosing a threshold

To get a binary edge image I keep the pixels of the gradient magnitude above a threshold. Figure 9 shows four choices.

The threshold trades noise against real edges. At 15 the fine texture of the grass and a few specks in the sky are strong enough to pass, so noise crowds the real edges. At 80 the noise is gone, but so is a lot of true structure: the details of the camera and the skyline at the horizon are broken up or missing. I chose 45. It removes most of the grass texture while keeping the cameraman's outline, the camera, the tripod legs and most of the horizon.

1.3 Derivative of Gaussian (DoG) filter

Finite differences amplify noise, which is why the edge maps in Part 1.2 pick up the texture of the grass. Blurring first suppresses it. I built a 13×13 Gaussian with σ = 2 as the outer product of the 1D kernel from cv2.getGaussianKernel with itself,

G=ggT

blurred the image with it, and repeated the Part 1.2 procedure on the blurred result.

DoG filters

Convolution is associative, so blurring the image and then taking a finite difference is the same as convolving the image once with the Gaussian already convolved with the difference operator. I convolved the Gaussian with Dx and with Dy, using my own convolution from Part 1.1 with "full" padding, to get the two derivative of Gaussian (DoG) filters:

DoGx=G∗Dx DoGy=G∗Dy I∗DoGx = (I∗G)∗Dx

They come out 13×14 and 14×13, one row or column larger than the Gaussian because Dx and Dy have two entries.

Blurred against unblurred

Figure 12 compares the gradient magnitude and the binarized edges without blur (Part 1.2) and with it. The blurred gradients are much weaker, with a maximum of 39.6 against 221, so I used a lower threshold of 15 for them, chosen the same way as before, instead of 45. The blur and the derivatives here mirror the image at the border instead of zero padding it, so the blur doesn't darken the edges and no fake frame appears.

DoG results

Applying the DoG filters directly to the original image, in one convolution each, gives the same result as blurring first. The largest difference from the two-step version is 2.5e-13 for Ix, 2.1e-13 for Iy and 2.7e-13 for the magnitude, which is floating-point rounding, and none of the 285,156 pixels differ in the binarized edges.

What differences do you see?

Blurring removes the noise. Without it, the grass texture and the specks in the sky pass a low threshold, and it takes a high one (45) to get rid of them, which also thins out real edges. With the blur the grass produces almost no false edges, so a much lower threshold keeps the outline, the camera, the tripod and much of the horizon. The cost is sharpness. The edges come out several pixels wide instead of one or two, and small details such as the parts of the camera are smoothed into fewer, rounder shapes.
