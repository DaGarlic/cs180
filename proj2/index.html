1.1 Convolution from scratch

Convolving an image with a kernel means flipping the kernel, sliding it over the image, and at every position multiplying it against the pixels underneath and summing the result. Here it is written in numpy only, first with four nested loops and then with two, on a zero-padded copy of the image. scipy.signal.convolve2d is used only as the reference to check against, and cv2 only reads and saves images.

Padding

Both versions pad the image with zeros first so the kernel can be centered on the edge pixels.

Four loops

The outer two loops visit every output pixel, and the inner two loops walk over the kernel, accumulating one product at a time. The flip is the [::-1, ::-1] on the kernel, which reverses it along both axes. 

def convol_img(image, kernel, mode="same"):
    # Perform convolution of the image with the given kernel (four for loop implementation)
    kernel_h, kernel_w = len(kernel), len(kernel[0])
    padded_image = pad_img(image, kernel, mode)
    flipped_kernel = np.array(kernel)[::-1, ::-1]
    height = padded_image.shape[0] - kernel_h + 1
    width = padded_image.shape[1] - kernel_w + 1
    output_image = np.zeros((height, width))

    for i in range(height):
        for j in range(width):
            sum_val = 0.0
            for ki in range(kernel_h):
                for kj in range(kernel_w):
                    sum_val += padded_image[i + ki][j + kj] * flipped_kernel[ki][kj]
            output_image[i][j] = sum_val

    return output_image

Two loops

The two inner loops are replaced by one array operation. The kernel-sized window of the padded image at the current pixel is sliced out, multiplied elementwise with the flipped kernel, and summed with np.sum. 

def convol_img_2loops(image, kernel, mode="same"):
    # Perform convolution of the image with the given kernel (two for loop implementation)
    kernel_h, kernel_w = len(kernel), len(kernel[0])
    padded_image = pad_img(image, kernel, mode)
    flipped_kernel = np.array(kernel)[::-1, ::-1]
    height = padded_image.shape[0] - kernel_h + 1
    width = padded_image.shape[1] - kernel_w + 1
    output_image = np.zeros((height, width))

    for i in range(height):
        for j in range(width):
            output_image[i][j] = np.sum(padded_image[i:i + kernel_h, j:j + kernel_w] * flipped_kernel)

    return output_image

The kernels

The box filter averages a 9×9 neighborhood, so each entry is 1/81 and the kernel sums to 1. Dx and Dy are the finite difference operators. Because convolution flips the kernel, convolving with [1, -1] gives f(x) − f(x−1), the final value minus the initial one, so an edge that gets brighter to the right comes out positive. 

Dx = [[1, -1]]
Dy = [[1], [-1]]

def box_kernel(size):
    # Generate a 2D box filter kernel (every entry is 1 / size^2 so it sums to 1)
    kernel = []
    for i in range(size):
        row = []
        for j in range(size):
            row.append(1 / size**2)
        kernel.append(row)
    return kernel

Checking against scipy

The reference call zero-fills the border the same way the padding above does. All three implementations run on the same image and kernel, in both padding modes, and the largest difference between their outputs is taken. 

def convol_with_scipy(image, kernel, mode="same"):
    return scipy.signal.convolve2d(image, kernel, mode=mode, boundary="fill", fillvalue=0)

The four-loop version does one Python-level multiply-add per kernel entry per pixel, about 100 million of them for the 9×9 box filter, so its time grows with the kernel: 26 s for the box filter against about 1 s for the two-entry Dx and Dy. The two-loop version makes a handful of NumPy calls per pixel instead, so its time barely depends on the kernel, about 2.5 s for all three. That makes it roughly 10 times faster for the box filter, but about 2.5 times slower for Dx and Dy, where the four-loop version only has two products to add and NumPy's per-call overhead costs more than it saves. scipy is much faster than either: 0.084 s for the box filter, about 30 times faster than the two-loop version and 300 times faster than the four-loop one, and about 0.01 s for Dx and Dy, because its loops run in compiled code instead of Python.

Boundary handling

Both implementations pad with zeros, which is the fill convolve2d uses by default, so the outputs match scipy up to floating-point rounding (a largest difference of 6.3e-13 for the box filter and 0 for Dx and Dy). Zero padding only affects the outermost pixels: the box filter darkens the outer 4 pixels because it averages in zeros, and Dx and Dy pick up a one-pixel edge along the left and top border respectively. scipy can also reflect or wrap at the border, but only zero fill is implemented here.

1.2 Finite difference operator

The cameraman image is convolved with the finite difference operators from Part 1.1, using the four-loop convolution with "same" padding. Dx gives the partial derivative Ix of the image I in x and Dy gives the partial derivative Iy in y. The gradient magnitude, sqrt(Ix² + Iy²), combines the two into a single edge-strength image that doesn't depend on which way the edge points.

Choosing a threshold

A binary edge image keeps the pixels of the gradient magnitude above a threshold. Figure 9 shows four choices.

The threshold trades noise against real edges. At 15 the fine texture of the grass and a few specks in the sky are strong enough to pass, so noise crowds the real edges. At 80 the noise is gone, but so is a lot of true structure: the details of the camera and the skyline at the horizon are broken up or missing. Threshold 45 works best. It removes most of the grass texture while keeping the cameraman's outline, the camera, the tripod legs and most of the horizon.

Finite differences amplify noise, which is why the edge maps in Part 1.2 pick up the texture of the grass. Blurring first suppresses it. The Gaussian here is 13×13 with σ = 2, built as the outer product of the 1D kernel from cv2.getGaussianKernel with itself,

blurred the image with it, and repeated the Part 1.2 procedure on the blurred result.

DoG filters

Convolution is associative, so blurring the image and then taking a finite difference is the same as convolving the image once with the Gaussian already convolved with the difference operator. Convolving the Gaussian with Dx and with Dy, using the convolution from Part 1.1 with "full" padding, gives the two derivative of Gaussian (DoG) filters:

DoGx=G∗Dx DoGy=G∗Dy I∗DoGx = (I∗G)∗Dx

Here I is the input image, G is the Gaussian, Dx and Dy are the difference operators from Part 1.1, and ∗ is convolution. The filters come out 13×14 and 14×13, one row or column larger than the Gaussian because Dx and Dy have two entries.

Blurred against unblurred

Figure 12 compares the gradient magnitude and the binarized edges without blur (Part 1.2) and with it. The blurred gradients are much weaker, with a maximum of 39.6 against 221, so they use a lower threshold of 15, chosen the same way as before, instead of 45. The blur and the derivatives here mirror the image at the border instead of zero padding it, so the blur doesn't darken the edges and no fake frame appears.

DoG results

Applying the DoG filters directly to the original image, in one convolution each, gives the same result as blurring first. The largest difference from the two-step version is 2.5e-13 for Ix, 2.1e-13 for Iy and 2.7e-13 for the magnitude, which is floating-point rounding, and none of the 285,156 pixels differ in the binarized edges.

What differences do you see?

Blurring removes the noise. Without it, the grass texture and the specks in the sky pass a low threshold, and it takes a high one (45) to get rid of them, which also thins out real edges. With the blur the grass produces almost no false edges, so a much lower threshold keeps the outline, the camera, the tripod and much of the horizon. The cost is sharpness. The edges come out several pixels wide instead of one or two, and small details such as the parts of the camera are smoothed into fewer, rounder shapes.

2.1 Image sharpening

Unsharp masking sharpens an image by boosting its high frequencies. A Gaussian blur G keeps only the low frequencies, so subtracting the blurred image from the original leaves the high frequencies: the edges and fine texture that the blur removed. Adding some of that back sharpens the image, and α sets how much:

Isharp= I+α(I−I∗G) = (1+α)I−α(I∗G) = I∗((1+α)δ−αG)

Here δ is the unit impulse, a kernel with a 1 in the center and 0 everywhere else, so that I ∗ δ = I. Convolution is linear, so blurring, subtracting and adding back collapse into one convolution with the kernel (1 + α)δ − αG. That kernel sums to 1, so the overall brightness doesn't change. The kernel is built once and the image is convolved with it, mirroring the border. It matches blurring, subtracting and adding back to within 7e-13. 

def unsharp_kernel(size, sigma, alpha):
    # Unsharp mask as a single kernel. image + alpha * (image - image * G) is linear in the image, so it
    # equals image * ((1 + alpha) * impulse - alpha * G), where the impulse is a 1 at the center of the kernel
    kernel = -alpha * gaussian_kernel_cv(size, sigma)
    kernel[size // 2, size // 2] += 1 + alpha
    return kernel

def unsharp(image, kernel, sigma, alpha=1.0):
    # Apply unsharp masking with a single convolution, alpha is how much of the high frequencies to add back
    return convol_symm_with_scipy(image, unsharp_kernel(kernel, sigma, alpha))

2.2 Hybrid images

A hybrid image (Oliva, Torralba and Schyns, SIGGRAPH 2006) mixes the high frequencies of one image with the low frequencies of another. Up close the eye picks up the fine detail, so you see the first image. From far away that detail is too small to see, and only the low frequencies are left, so you see the second. The high frequencies of I1 are the image minus its Gaussian blur, which is the same as convolving it with an impulse minus a Gaussian. They are scaled by a gain k and added to the blur of I2:

H= k(I1−I1∗Gσ1) +I2∗Gσ2 = I1∗k(δ−Gσ1) +I2∗Gσ2

Here Gσ is a Gaussian with standard deviation σ pixels, δ is the unit impulse, and σ1 and σ2 set the two cutoff frequencies. The gain k sets how strong the first image is next to the second: at k = 1 the high frequencies are used as they are, and a pair that needs the first or the second image to stand out more gets a larger or smaller value. The blur is done as two 1D passes, because the σ needed here would make a single 2D kernel slow. 

def gaussian_blur(image, sigma):
    # Blur with a separable Gaussian (two 1D passes), much faster than one 2D kernel when sigma is large
    size = 2 * int(np.ceil(3 * sigma)) + 1
    kernel_1d = cv2.getGaussianKernel(size, sigma)
    return convol_symm_with_scipy(convol_symm_with_scipy(image, kernel_1d), kernel_1d.T)

def hybrid_image(im1, im2, sigma1, sigma2, gain=1.0):
    # High frequencies of im1 (the image minus its blur, times a gain that sets how strong they are next to the
    # low frequencies) plus the low frequencies of im2 (its blur)
    high = gain * (im1 - gaussian_blur(im1, sigma1))
    low = gaussian_blur(im2, sigma2)
    return high + low

2.3 Gaussian and Laplacian stacks

A Gaussian stack blurs an image with a wider Gaussian at each level. Unlike a pyramid it never subsamples, so every level keeps the full size of the image and all the levels sit in one array. Level 0 is the image itself, and each level after it blurs the original with a Gaussian twice as wide as the one before. A Laplacian stack takes the difference between neighboring Gaussian levels, so each level holds one band of frequencies, and it keeps the blurriest Gaussian level at the end. The levels add back up to the image:

Li=Gi−Gi+1 LN=GN I= ∑i=0N Li

Neither stack uses cv2.pyrDown or skimage.transform.pyramid_gaussian. Each blurred level uses the separable Gaussian blur from the hybrid images, and there are five levels in all. The Laplacian levels add back to each image to within about 1e-16. 

def gaussian_stack(image, levels, sigma=4):
    # Gaussian stack: level 0 is the image, and every level after it blurs the image with a Gaussian twice as wide as
    # the level before. Nothing is subsampled, so all levels keep the size of the image
    stack = [image]
    for i in range(1, levels):
        stack.append(gaussian_blur(image, sigma * 2 ** (i - 1)))
    return np.array(stack)

def laplacian_stack(gaussian):
    # Laplacian stack: the difference between neighboring Gaussian levels, with the blurriest Gaussian level kept at the
    # end, so the levels add back up to the image
    stack = []
    for i in range(len(gaussian) - 1):
        stack.append(gaussian[i] - gaussian[i + 1])
    stack.append(gaussian[-1])
    return np.array(stack)

def blend_stacks(laplacian_a, laplacian_b, mask_gaussian):
    # Blend two Laplacian stacks level by level, weighting level i of the first by level i of the mask's Gaussian stack
    # and level i of the second by what is left. Returns every blended level, and their sum is the blended image
    mask = mask_gaussian[..., np.newaxis]
    return mask * laplacian_a + (1 - mask) * laplacian_b
